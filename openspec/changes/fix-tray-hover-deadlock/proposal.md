# Proposal

## Why

Windows 打包版运行一段时间后出现托盘悬浮、右键菜单和双击打开主窗口同时无响应，现场进程被系统标记为未响应。代码存在后台持有悬浮状态锁并同步等待界面线程、界面线程同时等待该锁的死锁路径，需要消除这一风险并验证打包版交互稳定性；本次现场尚无调用栈，不能把日志中的 Windows 1460 超时直接认定为该死锁的证明。

## What Changes

- 缩小托盘悬浮状态锁的范围，所有可能等待界面线程的窗口、显示器查询与操作均在锁外执行。
- 使用现有 generation 校验异步悬浮请求，保证查询期间发生移出、点击、关闭或新请求时，过期任务不会继续打开面板或覆盖新状态。
- 补充能够覆盖并发取消和界面查询交错的回归验证，以及 Windows 打包版托盘交互验收记录。
- 保留现有悬浮延迟、隐藏宽限期、菜单行为和窗口布局。

## Capabilities

### New Capabilities

- `tray-interaction-liveness`: 规定托盘并发交互的响应性、过期悬浮任务取消行为及后台刷新期间的可用性。当前正式规范目录无已登记能力；已有未归档 MVP 的 `desktop-shell` 仅描述基本托盘入口，本变更新增独立的响应性约束，不重复其入口定义。

### Modified Capabilities

无。

## Impact

- 主要影响 `src-tauri/src/tray/mod.rs` 的延迟悬浮任务和共享状态处理；按需调整 `src-tauri/src/windows/mod.rs` 的窗口查询调用边界。
- 测试与诊断仅围绕托盘并发路径，日志不得记录凭据或连接配置。
- 无数据库迁移、外部 API 变更或新增运行时依赖；不包含发布、自动更新部署或托盘自动重建机制。
