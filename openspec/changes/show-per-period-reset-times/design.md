# Design

## Context

本设计用于让两处汇总展示复用现有周期数据，动机见 `proposal.md` 的 Why。

| 位置 | 已有行为 | 本次接入点 |
| --- | --- | --- |
| `src-ui/src/types.ts` | 每个账号具有 `windows`，每个窗口具有独立 `resetAt` | 直接消费已有数据，无需新增字段 |
| `src-ui/src/views/ManagementView.vue` | 周期列只显示百分比；首列显示优先窗口时间 | 周期列增加时间，首列改为“优先重置” |
| `src-ui/src/views/HoverPanelView.vue` | 三个周期块只显示百分比；元信息显示一个重置时间 | 周期块增加时间，原时间明确标注 |
| `src-ui/src/styles.css` | 表格周期列仅 54px，悬浮块为单行且设置省略号 | 扩展周期列宽，周期块改为双行 |
| `src-tauri/src/providers/volcengine.rs` | AFP 五小时窗口使用 `afp-five-hour`、“5 小时 AFP”，没有周期秒数 | 前端补齐已有标识识别，不改提供方 |

管理页的模型额度卡片已经逐窗口显示 `resetAt`，无需重做。两处汇总均先按订阅到期时间排序，再按优先窗口重置时间排序；本次保持该流程。

## Goals / Non-Goals

**Goals:**

- 周期额度与时间从同一个窗口读取，管理页和悬浮详情共用最小的识别、选择与格式化逻辑。
- 在现有窗口尺寸下提供可读的双行信息，避免把三个重置时间挤在原单一时间位置。
- 为缺失、无效、过去时间及提供方别名提供可回归的边界。

**Non-Goals:**

- 不修改后端模型、数据库、提供方请求、快照或关键额度汇总。
- 不从订阅到期、更新时间或周期时长推算重置时间；不承诺所有提供方都返回三种周期。
- 不把“当前会话”或“短期用量”默认当作 5 小时，不新增每日周期列。
- 不改排序策略、账号筛选、流量球轮播或全局日期格式。

## Decisions

### 1. 复用窗口级时间，保留汇总字段原义

各周期取值路径固定为：账号 → 对应周期窗口 → 该窗口的 `remainingPercent` 与 `resetAt`。周期时间不回退到 `nextResetAt`、`nearestResetAt`、`subscriptionUntil` 或其他窗口。这些字段继续服务原有汇总、优先重置和订阅信息。

备选方案是在后端增加三个顶层时间字段；这会重复已有数据并扩大接口与持久化修改，因此不采用。

### 2. 抽取轻量共享周期工具

建议在 `src-ui/src/utils/quotaPeriod.ts` 放置周期键类型、识别、窗口选择和新增时间格式化函数，两处页面引用。不要抽取账号排序、额度汇总或通用渲染组件。

- 优先识别明确周期类型，再识别明确秒数，最后使用现有标识和名称别名。每日类型不进入三个周期。
- 五小时覆盖 18000 秒、`5h`、`5 h`、`five-hour`、`5 小时`；周覆盖 weekly、604800 秒、`7d`、week、每周、近 1 周；月覆盖 monthly、2592000 秒、`30d`、month、每月、近 1 月。秒数仅用于识别提供方已给出的周期，不能用于推算重置日期。
- `afp-five-hour` 即使 `periodSeconds` 为空也能正确识别；不凭 session 或短期名称推断五小时。
- 同一周期有多个窗口时沿用目前按数组顺序选择首个匹配窗口的行为，额度和时间均来自该窗口。即使其时间缺失，也不改选另一个窗口的时间。
- 工具仅只读数据，不改窗口排序、关键窗口标识或活动状态筛选规则。识别修正可能让原本漏识别的数据归入正确周期，但不改变排序算法。

备选方案是两处分别新增函数；已有周期识别重复正是展示不一致的风险，因此只抽取本次共用的少量纯函数。

### 3. 周期列与周期块采用双行展示

管理页保留现有账号行和优先信息，在三个周期列中上方显示剩余百分比，下方显示本周期重置时间；首列标题从“重置时间”调整为“优先重置”。同步调整说明文案，明确三个周期时间与优先时间的区别。

悬浮详情继续使用三个并排周期块，每块第一行是名称和百分比，第二行是本周期时间。元信息中的原“重置”改为“优先重置”，账号到期和更新仍独立显示。

备选方案是新增三个独立时间列或把账号拆成三个表格行；前者扩张表宽，后者重复账号信息，因此使用现有周期位置。

### 4. 新增时间按周期长度使用独立阈值

新增周期时间先校验 `new Date(value).getTime()` 为有限且大于零，随后以本地时区固定展示 `MM/DD HH:mm`。不存在或校验失败显示 `--`，过去的有效时间照实显示。格式化只针对本次周期时间，不修改已有订阅和更新日期逻辑。

剩余百分比继续使用 `windowClass` 的原有额度预警色。周期时间按自身 `resetAt` 计算距离，并使用与周期长度匹配的阈值：

| 周期 | 紧急 `critical` | 警告 `warning` | 健康 `healthy` |
| --- | --- | --- | --- |
| 5 小时 | 小于等于 1 小时 | 大于 1 小时且小于等于 3 小时 | 大于 3 小时 |
| 周 | 小于等于 1 天 | 大于 1 天且小于等于 3 天 | 大于 3 天 |
| 月 | 小于等于 3 天 | 大于 3 天且小于等于 7 天 | 大于 7 天 |

缺失或无效时间为 unknown。过去时间视为已经紧急，不自动推算下次重置。原“优先重置”如果能识别对应窗口周期，则使用该周期阈值；无法识别或只能使用账号汇总时间时，保留 3 天/7 天通用阈值。周期时间不继承账号行、额度百分比或其他周期的颜色。

备选方案是所有周期共用 3 天/7 天阈值；这会导致 5 小时周期几乎始终为紧急色，无法表达其周期内相对远近，因此不采用。

### 5. 局部布局调整和回归

扩大管理页三个周期列到足以容纳日期时间的宽度，并调整表格最小宽度与现有横向滚动容器。悬浮块第二行完整显示紧凑时间，不应用单行省略号；必要时局部调整字体、内边距和元信息网格，不全局取消账号名称的截断。账号列表继续纵向滚动。

用轻量自动化用例验证共享工具，不新增运行时依赖；项目没有现成前端测试脚本，实施时使用已有 TypeScript 工具链配合 Node 原生断言或测试运行器，记录可重复执行的入口。布局采用本地合成快照验收，不使用真实凭据。

## Risks / Trade-offs

- [提供方不返回重置时间] → 对应位置显示 `--`，不误用月度到期或账号汇总时间。
- [同周期有多个额度窗口] → 保留首匹配行为，百分比和时间严格同源；多模型窗口的聚合选择不在本次范围。
- [两处宽度有限] → 管理页采用双行列和横向滚动；悬浮详情采用紧凑时间与双行块，验收时检查完整可读。
- [别名匹配误归类] → 明确类型和秒数优先，覆盖每日、session、短期名称反例。
- [样式继承把时间染成额度预警色] → 周期时间只绑定基于自身 `resetAt` 的时间状态类，并用局部选择器覆盖账号行和额度百分比颜色。
- [缓存中的时间已过去] → 保留真实日期及原缓存提示，不制造新的恢复时间。

## Migration Plan

本变更仅涉及前端展示与共享工具，无数据迁移或新增配置。实施后执行共享工具回归、`npm run typecheck` 和 `npm run build`，再验证两处布局、账号排序、模型额度卡片及缓存提示。

部署使用现有桌面构建和发布流程；回退到上一版前端即可恢复原展示，不需要恢复数据库或提供方配置。
