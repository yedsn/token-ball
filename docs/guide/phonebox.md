# PhoneBox 手机额度面板

把 TokenBall 已采集的额度显示到 PhoneBox 手机页面。只需升级 TokenBall 并导入页面，PhoneBox Agent 与 Android 应用不需要定制。

## 接入流程

前置条件：TokenBall 与 PhoneBox Agent 在同一台电脑运行，至少配置一个额度实例；手机通过 PhoneBox 原有 USB 或 Wi-Fi 方式配对。

1. 在 TokenBall 管理窗口打开“设置 → 常规 → PhoneBox 手机额度面板”。
2. 勾选“启用额度推送”，填写 Agent 地址，通常为 `http://127.0.0.1:8765`，点击“保存 PhoneBox 设置”。
3. 点击“立即推送”，查看最近尝试、最近成功及错误提示。这个按钮只发送已有缓存，不额外调用平台额度接口；要采集新额度，请使用原来的刷新功能。
4. 打开 PhoneBox 设置的 **Webhooks**，确认出现 `tokenball`。也可在本机访问 `http://127.0.0.1:8765/api/push/tokenball` 验证 `data.schema` 为 `tokenball.phonebox.v1`。
5. [下载 TokenBall 页面模板](/integrations/phonebox/tokenball-page.json)，在 PhoneBox 的 **Pages → Import** 中选择文件。出现 Custom HTML 信任提示时，确认来自本项目后选择保留；出现“替换全部页面”提示时选择 **Cancel（追加）**，然后保存。源码文件为 `integrations/phonebox/tokenball-page.json`。
6. 打开 **Live preview** 或切到手机的 TokenBall 页面，核对账号数量、各周期余量和“实际采集”时间。PhoneBox 导入会询问替换还是追加，请选择追加以保留现有页面。

只想显示总体余量时，也可以自己添加 **Pushed value** 组件，将 key 设置为 `tokenball`。详细模板使用内置 **Custom HTML** 组件，无需访问 TokenBall 本机端口。

## 设置与运行行为

| 项目 | 默认值 / 行为 |
| --- | --- |
| 开关 | 默认关闭；保存后立即生效，不需要重启 |
| Agent 地址 | `http://127.0.0.1:8765`；仅支持字面量 `127.0.0.1` 或 `[::1]` 的 HTTP 根地址，可指定端口，不支持 `localhost`、远程地址、路径、参数和片段 |
| 鉴权 | 同机 PhoneBox 推送接口不需要密钥；不发送任何平台鉴权信息 |
| 触发 | 启动、开启/修改配置、额度刷新完成（含失败）、实例保存/启停/删除/导入以及立即推送 |
| 心跳 | 每 60 秒重发当前缓存，PhoneBox 晚启动或重启后自动恢复；不是每分钟向平台采集 |
| 超时 | 单次请求 3 秒；失败等待下次事件或心跳，不紧密重试 |
| 后台 | 隐藏悬浮窗或关闭管理窗口不停止推送；彻底退出 TokenBall 会停止 |
| 停用 | 取消未完成投递并停止心跳；PhoneBox 中原值最多 180 秒后自动过期，不清空其他数据 |

设置独立保存在 TokenBall SQLite 的 `settings` 项 `integration.phonebox`；不改变现有显示设置或连接备份格式。仅同机回环 HTTP、禁止环境代理与重定向，避免数据被转发到其他机器。

## 展示口径

- 范围是所有启用实例的账号，不跟随悬浮球勾选的账号；账号显示 TokenBall 中的名称（移除控制字符、最多 160 个字符，名称可能含邮箱），实例使用稳定通用别名。旧版负载缺少名称时回退为账号别名。
- 账号轮播顺序与托盘一致：订阅到期时间升序 → 优先额度恢复时间升序 → 账号名称按中文排序；缺失时间排在最后。优先恢复时间先取月周期，否则取带恢复时间的最高优先级窗口（已识别周期按时长，其余按 periodSeconds、total），都没有时回退为账号 nextResetAt；它仅用于排序，不替代任何周期的恢复时间。收到新推送或顺序变化时保留当前查看的账号。
- 平均关键余量：每个账号取原关键窗口，已知百分比求平均，未知值不参与分母。80%、20%、未知三个账号的平均是 50%，不是 33%。
- 已知额度等效账号：已知关键百分比之和除以 100，上例为 1.0；它不是不同平台 Token 总数的累加。
- 全部未知时平均余量和等效账号显示 `--`，不将未知当作耗尽。可用账号按 available/warning 状态计数。
- 5 小时、周、月分别显示对应窗口的余量和恢复时间。没有该周期或恢复时间缺失时显示 `--`，不借用其他周期、订阅到期或账号汇总时间。
- 倒计时结束只提示“等待额度刷新”，不会自动把余量变为 100%。
- “推送在线”只说明 TokenBall 近期投递成功，不代表平台刚刚采集。每个账号保留真实采集时间；平台异常、采集时间缺失或超期均标为缓存/异常。
- 过期宽限为：采集时间加 `max(300, 同步间隔 + 已启用的最大随机延迟 + 300)` 秒。模板在两次推送之间也会自行更新过期提示。

### 状态颜色

颜色参考 TokenBall 托盘面板，余量与恢复时间独立判断；同一周期可能出现绿色余量、红色恢复时间，不代表字段冲突。

| 内容 | 红色 | 黄色 | 绿色 |
| --- | --- | --- | --- |
| 总体 / 周期余量 | 小于 30% | 30% 至小于 60% | 60% 及以上 |
| 5 小时恢复时间 | 距离恢复 ≤1 小时 | >1 至 ≤3 小时 | >3 小时 |
| 周恢复时间 | ≤24 小时 | >24 至 ≤72 小时 | >72 小时 |
| 月恢复 / 订阅到期 | ≤3 天 | >3 至 ≤7 天 | >7 天 |
| 实际采集时间 | 超过 1 小时，或该账号缓存过期 / 连接异常 | — | 采集时间有效且未达到左侧条件 |

缺失时间和未知额度为灰色，未知额度显示虚线环；周期余量颜色与托盘相同，按四舍五入后的百分比判断，总体按原始平均值判断。恢复时间到点后保留红色并提示等待刷新，不自动补满额度。账号可用为绿、预警/冷却/缓存为黄、耗尽/登录失效/离线/错误为红；文字状态不会因颜色而省略。颜色和倒计时每秒本地更新。

## v1 推送协议

用途是向现有 PhoneBox 写入只读展示数据，不提供 TokenBall HTTP 服务，也不让手机管理账号或触发平台请求。

| 项目 | 内容 |
| --- | --- |
| 方法 / 路径 | `POST /api/push/tokenball?ttl=180` |
| 请求格式 | `Content-Type: application/json`，UTF-8 |
| 成功确认 | 2xx 且响应 JSON 含 `ok: true`、`key: "tokenball"`；其余为投递失败 |
| 失败 | 连接、超时、HTTP 错误或确认格式错误显示在 TokenBall；不改变 Provider 状态 |
| 体积 | 最大 60 KiB，低于 PhoneBox 的 64 KiB 限制；超量省略完整账号并报告数量，汇总仍覆盖全部启用账号 |

| 字段 | 含义 |
| --- | --- |
| `schema` | 固定 `tokenball.phonebox.v1` |
| `title/value/unit/progress/sub/level` | 供普通推送组件展示；未知 value 为 `--`，已知 progress 范围 0–1 |
| `pushedAt / heartbeatTimeoutSeconds` | 本次投递时间 / 180 秒，仅判断传输在线 |
| `summary` | 账号数、可用数、已知数、平均百分比、等效账号数、缓存状态 |
| `accounts[]` | 不透明 ID、备用别名、账号展示名称 displayName、平台、实例别名、套餐、账号/连接状态、真实采集/过期/订阅时间及周期数据 |
| `accounts[].priorityResetAt` | 与托盘一致的优先恢复时间，仅用于账号排序；缺失为 null |
| `accounts[].periods` | `fiveHour/weekly/monthly`，各自独立额度、单位及 resetAt；缺失为 null |
| `includedAccountCount / omittedAccountCount` | 详情实际包含 / 容量原因省略的账号数量 |

账号展示名称按用户要求发送；如果名称本身包含邮箱，该邮箱也会显示在 PhoneBox 上。除此之外，不发送独立邮箱字段、Management Key、Cookie、AK/SK、原实例名称、externalId、ChatGPT ID、连接地址、原始平台响应和请求历史；套餐名为限长纯文本。投递日志不记录展示负载。模板不加载外部字体/脚本/图片、不发网络请求、不执行快捷指令，动态字段仅按文本渲染。

## 故障与回滚

| 现象 | 处理 |
| --- | --- |
| 无法连接 | 确认 Agent 在同机运行、端口正确；下次心跳会重试，也可立即推送 |
| 地址无效 | 使用 `http://127.0.0.1:8765`，不要填 `/api/push`，不要使用 localhost |
| 已投递但手机没数据 | 在 Webhooks 检查 tokenball；确认导入后保存、手机连接到正确电脑、组件 key 正确 |
| 账号仍是摘要编号或顺序不一致 | 同时使用更新后的 TokenBall 和页面模板，并在 TokenBall 中立即推送；仅重新导入模板不能恢复旧负载中未发送的账号名称和排序信息 |
| 推送在线但账号显示缓存 | 检查该平台登录态、连接状态和真实采集时间；重新推送不会刷新平台缓存 |
| 版本不兼容 | 重新导入与 TokenBall 匹配的页面模板 |
| 省略部分账号 | 超过单条容量限制；汇总不受影响，第一版不拆分多个 key |
| 关闭后仍有内容 | 等待最多 180 秒 TTL，或在 PhoneBox Webhooks 中手动删除 tokenball |

回滚时关闭集成即可；需要时在 PhoneBox 删除导入的 TokenBall 页面，不影响其他页面和数据。降级 TokenBall 不改变原 Provider 配置。

## 开发验证与兼容性

模板源码为 `integrations/phonebox/tokenball-widget.html`；`npm run phonebox:generate` 同步生成仓库导入文件与文档下载文件，`npm run phonebox:check` 检查一致性。`npm run test:phonebox` 验证状态/时间/文本安全，Rust PhoneBox 测试验证配置、脱敏、计算、容量和投递恢复。

协议依据 PhoneBox 源码 `1836f00`（项目版本 0.9.29）的推送、页面导入与 HTML 沙箱实现。模拟投递与原版 HTML 组件沙箱检查通过，但实际 Agent 的导入/重启/TTL 整体联调及 USB/Wi-Fi 真机尚未验收，不宣称所有旧版本均已验证；详见仓库 `openspec/changes/add-phonebox-quota-push/verification.md`。
